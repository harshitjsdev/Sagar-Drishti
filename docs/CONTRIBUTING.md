# Contributing

Thank you for helping improve SagarDrishti.

## Workflow

1.  Review the overview and architecture documents.
2.  Check repository issues/discussions if available.
3.  Create a branch for a focused change.
4.  Keep changes clear and limited in scope.
5.  Run applicable tests and scientific checks.
6.  Test the user flow in a supported browser.
7.  Update documentation for changes to routes, configuration, features
    or data behaviour.
8.  Submit a pull request with a summary and testing notes.

## Scientific and educational contributions

-   Cite sources and preserve provenance.
-   Distinguish measurements from model output.
-   Use age-appropriate language.
-   Avoid unsupported claims.
-   Seek educator/domain review where practical.
-   Label AI-generated or illustrative examples.

## Security

Never commit keys, passwords, tokens or private learner records. Report
suspected vulnerabilities privately to maintainers rather than posting
exploit details publicly.

## Pull request checklist

-   [ ] Purpose is clear.
-   [ ] No secrets or personal data added.
-   [ ] Applicable checks run.
-   [ ] Scientific labels and provenance remain accurate.
-   [ ] Error/fallback states considered.
-   [ ] Documentation updated.
-   [ ] New features are not described as complete unless implemented
    and verified.
